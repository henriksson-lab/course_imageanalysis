# Plan: a day on support vector machines

Internal working doc (plan/ is not rendered). Status: draft for discussion, 2026-11-12.

## Goal of the day

After the day a student can:

1. say how image analysis turns into **classification**: a pixel described by a stack of filter responses, an object by its measured features, a window by a patch descriptor; and that a **threshold on one feature is already a linear classifier**;
2. read a **linear classifier** $f(\mathbf x) = \mathbf w\cdot\mathbf x + b$ geometrically (normal vector, offset, signed distance $f(\mathbf x)/\|\mathbf w\|$ to the hyperplane), and draw it for a small 2D example;
3. explain the **maximum-margin** idea, find the max-margin line and the **support vectors** of 3–4 points **by hand**, and say what the slack penalty $C$ trades off (the **hinge loss** compared with the 0–1 and logistic losses);
4. explain the **kernel trick**: compute an explicit quadratic feature map by hand and check that its dot product equals the kernel; describe the **RBF kernel** with $\gamma$ as an inverse squared length scale, and predict what large $\gamma$ or large $C$ do (overfitting);
5. train and evaluate a classifier honestly: **feature scaling**, **cross-validation** for $(C, \gamma)$, class **imbalance**, **multi-class** by one-vs-rest / one-vs-one, and evaluation by confusion matrix and ROC; apply this to **pixel classification** of a micrograph.

*(math)* for students who take the math layer: write the hard- and soft-margin primal problems, derive the **dual** with Lagrange multipliers, and see that the data enter only through dot products.

Why it fits this audience: the whole day is **geometry of hyperplanes** (dot products,
projections, distances from linear algebra) plus one constrained minimisation (calculus).
The kernel trick is "a dot product in a space we never write down", which is a linear
algebra statement. No machine learning is assumed (audience.md): the day introduces the
words *feature*, *training set*, *test set*, *overfitting* and *cross-validation* for
classifiers, so other days can use them.

## Prerequisite gap

- **Dot product, projection, distance to a hyperplane**: assumed (linear algebra). One recall slide with the 2D picture: $\mathbf w$ is the normal, $\mathbf w\cdot\mathbf x$ is (a multiple of) the projection on it.
- **Lagrange multipliers**: *assumption to confirm*: audience.md lists partial derivatives and the gradient but not constrained optimisation. Most students will have seen equality-constrained Lagrange multipliers in multivariable calculus; **inequality constraints (KKT) and convex duality are not assumed**. Unit 2/3 math layer has one recall slide ("at the optimum the gradient of the objective is a combination of the constraint gradients") and states KKT complementary slackness in words ("a multiplier is non-zero only where the constraint is tight"). The concept layer never needs it.
- **Filters as features**: Gaussian smoothing, derivatives (Sobel), Laplacian are known from `kernels/`. The **LoG**, **difference of Gaussians** and **Hessian eigenvalues** at several scales are used in unit 4 as a feature stack: one slide each, as pictures ("blob detector", "ridge detector"), with a pointer to the day that owns them (wavelets day `atrous`/LoG, skeleton day Gaussian second derivatives).
- **Overfitting**: met informally in `neuralnet/` (E2 in the exercise: fitting the noise). Recalled in one line in unit 1, made precise with train/test error in unit 4.
- **Vocabulary clash 1: "kernel"**. `kernels/` is the convolution kernel. Here "kernel" means a similarity function $K(\mathbf x, \mathbf z)$. Say so explicitly on the first kernel slide; name the unit folder `kernel-trick/`, not `kernels/`.
- **Vocabulary clash 2: "hinge"**. `neuralnet/` calls a ReLU unit a *hinge*. The hinge loss $\max(0, 1 - yf)$ is literally a ReLU of $1 - yf$: use this as a link ("the same bend"), not as a source of confusion.

## Units (one folder each: lec, quiz, exercise with #explore)

Four core units, about 1.5 h each including the exercise, plus one optional unit.

### 1. `classify/`: Classification in image analysis and linear classifiers

- Three ways image analysis becomes classification, one picture each: (a) **pixels**: each pixel gets a feature vector from a stack of filtered images (intensity, smoothed at several scales, edges, blobs); (b) **objects**: each segmented object is a row of the measurement table (area, mean intensity, form factor, texture); (c) **windows**: a patch around each position is described by a vector (e.g. histograms of gradient directions) and classified "cell / not cell". All three: a point in a feature space, with a label.
- Recall (thresholding day): a threshold on intensity is a classifier in 1D: $f(x) = x - t$, decide by the sign. In 2D, a line; in $d$ dimensions, a hyperplane: $f(\mathbf x) = \mathbf w\cdot\mathbf x + b$.
- Geometry: $\mathbf w$ is the normal; $b$ shifts the line; $f(\mathbf x)/\|\mathbf w\|$ is the signed distance; scaling $(\mathbf w, b)$ by $c > 0$ changes nothing about the decision (important for unit 2). Small numeric example: $\mathbf w = (1, 2)$, $b = -4$: classify three points, compute their distances.
- Training set, test set, error rate (0–1 loss). Many lines separate the training points: which one? Nearest class mean (moments day) is one answer ($\mathbf w = \boldsymbol\mu_+ - \boldsymbol\mu_-$, through the midpoint); 1-NN gives a non-linear boundary; the max-margin line (unit 2) is another. Generative vs discriminative (GMM day) in one slide.
- When no line works: XOR, a ring around a blob (the nucleus/cytoplasm case in intensity alone). Sets up unit 3.
- **The math: hyperplanes**: distance formula $|\mathbf w\cdot\mathbf x + b|/\|\mathbf w\|$ from the projection; nearest class mean as a linear rule (expand $\|\mathbf x - \boldsymbol\mu_+\|^2 < \|\mathbf x - \boldsymbol\mu_-\|^2$).
- **Demo `linclass`** (new, small): a 2D scatter of two classes (presets of seeded point sets); the line drawn from a draggable normal arrow $\mathbf w$ and a draggable point on the line (sets $b$); shaded half-planes; each point shows its signed distance on hover-free labels (toggle); readout: number of errors, smallest distance to the line. Buttons: *nearest class mean*, *1-NN boundary* (shaded regions), *perceptron step* (one update, optional). Presets: "many lines are perfect", "nearest mean is not the best line", "one outlier", "XOR: no line works", "ring around a blob". Feature axes can be labelled (e.g. "mean intensity", "area") via `data-axes`.
- By hand: (a) for $\mathbf w = (1, 2)$, $b = -4$, classify 4 given points and compute their signed distances; (b) nearest class mean line for two classes of 3 points each; (c) a 1D threshold $t = 100$ written as $(w, b)$; (d) *(math)* show that nearest class mean is linear and find $\mathbf w, b$.

### 2. `maxmargin/`: Maximum margin, support vectors and the soft margin

- Picture first: of all separating lines, take the one with the widest empty **street** around it. Only the points on the edge of the street matter: the **support vectors**. Move any other point (without crossing the street): nothing changes. Move a support vector: the line moves.
- Why wide: robustness to noise in the features, and (stated, not proven) better generalisation.
- Fix the scale of $(\mathbf w, b)$ so that $f = \pm 1$ on the street edges; the street has width $2/\|\mathbf w\|$. Widest street = smallest $\|\mathbf w\|$ with every training point on its side: $y_i f(\mathbf x_i) \ge 1$.
- Worked example by hand: $+1$ at $(2, 0), (3, 1)$; $-1$ at $(0, 0), (0, 1)$. Max-margin line $x_1 = 1$, $\mathbf w = (1, 0)$, $b = -1$, width 2, support vectors $(2, 0), (0, 0), (0, 1)$; check $y_i f(\mathbf x_i)$ = 1, 2, 1, 1.
- **Soft margin**: real data overlap. Allow points inside the street or on the wrong side, at a price $C$ per unit of violation (slack $\xi_i$). Small $C$: wide street, many violations tolerated, smooth; large $C$: narrow street, few violations, sensitive to outliers. Support vectors now = all points on or inside the street.
- **Losses**: the soft-margin SVM minimises $\tfrac12\|\mathbf w\|^2 + C\sum_i \max(0,\, 1 - y_i f(\mathbf x_i))$. The **hinge loss** is zero for points safely outside the street and grows linearly inside. Compare: 0–1 loss (what we care about, but flat and jumpy: cannot be minimised by walking downhill), logistic / cross-entropy loss (the neural-network day's loss: never exactly zero, so every point has a say), squared loss (penalises points that are "too correct"). The hinge is a ReLU of $1 - yf$ (link to `neuralnet/`).
- Small numeric example: five points with given $y_i f(\mathbf x_i) = 2, 1, 0.5, 0, -1$: hinge, 0–1 and logistic losses in a table.
- **The math: hard-margin primal**: $\min \tfrac12\|\mathbf w\|^2$ s.t. $y_i(\mathbf w\cdot\mathbf x_i + b) \ge 1$; a convex quadratic problem: one optimum, no local minima (contrast with networks).
- **The math: soft margin**: slack $\xi_i \ge 0$, $y_i f(\mathbf x_i) \ge 1 - \xi_i$, objective $+C\sum\xi_i$; eliminating $\xi_i$ gives the unconstrained hinge form (regularised loss). Subgradient descent on it in one line (the demo's "train linear by descent" mode).
- **Demo `svm2d`** (new, main demo of the day; used again in units 3 and 4 with other `data-*` settings): canvas, click to add points (left/right button or a class toggle; touch-friendly class switch), drag to move, delete mode. Shows the decision line, the two margin lines, the street shaded, support vectors ringed, slack shown as a short segment from violating points to their margin, and the decision value $f$ as a faint background colour. Slider $C$ (log scale, $10^{-2}$–$10^3$). Readouts: width $2/\|\mathbf w\|$, number of support vectors, training errors. Unit 2 setting: `data-kernel="linear"` only. Presets: "the by-hand example", "move a non-support vector: nothing happens", "one outlier: hard vs soft", "overlapping classes: sweep C", "C large = narrow street". Training by SMO on every edit (≤ 300 points: well under 30 ms).
- **Demo `hingeloss`** (new, small): plot of loss against the margin value $y f$ for 0–1, hinge, logistic, squared (toggles); below, a 1D data set on a line with a draggable threshold and slope; each point's loss shown as a bar; total loss for each loss function. Presets: "an outlier far on the wrong side: hinge vs squared", "points far on the right side: logistic still pulls", "0–1 has flat steps".
- By hand: (a) find the max-margin line, margin width and support vectors for 3–4 given points; (b) is a given line the max-margin line? (check: equal distance to the closest point of each class, and are those closest points "balanced"); (c) hinge losses for a table of $y_i f(\mathbf x_i)$; (d) predict what happens to the line when $C$ goes from 100 to 0.01 with one outlier; (e) *(math)* show that the street width is $2/\|\mathbf w\|$.

### 3. `kernel-trick/`: The dual, kernels and non-linear boundaries

- Picture first (**demo `svmlift`**): points inside a ring cannot be split by a line in 2D. Add a third coordinate $x_1^2 + x_2^2$: the points lift onto a paraboloid, and a **plane** separates them. The plane cut back down to 2D is a circle.
- General idea: map $\mathbf x \mapsto \varphi(\mathbf x)$ to more features, then fit a linear classifier there. Problem: the quadratic map of a 20-feature pixel already has 230 coordinates; degree 5 has tens of thousands.
- Key fact (stated in the concept layer, derived in the math layer): the SVM solution is $f(\mathbf x) = \sum_i \alpha_i y_i\, \mathbf x_i\cdot\mathbf x + b$, with $\alpha_i > 0$ only for **support vectors**. Training and prediction need **only dot products** between data points. Replace every dot product by a **kernel** $K(\mathbf x, \mathbf z) = \varphi(\mathbf x)\cdot\varphi(\mathbf z)$ computed directly: the **kernel trick**.
- By hand: $\varphi(\mathbf x) = (x_1^2, \sqrt2\,x_1x_2, x_2^2)$; for $\mathbf x = (1, 2)$, $\mathbf z = (3, 1)$: $\varphi(\mathbf x)\cdot\varphi(\mathbf z) = 9 + 12 + 4 = 25 = (\mathbf x\cdot\mathbf z)^2$. Polynomial kernel $(\mathbf x\cdot\mathbf z + c)^p$.
- **RBF (Gaussian) kernel** $K(\mathbf x, \mathbf z) = e^{-\gamma\|\mathbf x - \mathbf z\|^2}$: a similarity, 1 for identical points, $\to 0$ far apart. $1/\sqrt{\gamma}$ is a **length scale**: "how far does one training point's influence reach". $f(\mathbf x)$ = signed sum of Gaussian bumps on the support vectors. Small $\gamma$: almost linear; large $\gamma$: an island around every training point (memorises: overfitting). Link: this is the graph-cut n-link weight and the `ncut` affinity with $\gamma = 1/2\sigma^2$; the **kernel matrix** $K_{ij}$ is the `ncut` matrix $W$.
- Numeric example: two support vectors $(0,0)$ with $\alpha y = +1$ and $(2,0)$ with $\alpha y = -1$, $b = 0$, $\gamma = 1$: evaluate $f$ at $(0.5, 0)$, $(1, 0)$, $(1, 1)$.
- What makes a valid kernel (**Mercer**, intuition): it must behave like a dot product somewhere: every kernel matrix must be symmetric with no negative eigenvalues (no "negative squared lengths"). Sums and products of kernels are kernels. One example of an invalid "similarity".
- $(C, \gamma)$ together: a 2D map of outcomes (underfit / good / overfit) as a picture; leads to cross-validation in unit 4.
- **The math: Lagrange multipliers and the dual**: recall slide (equality constraints, $\nabla f = \lambda\nabla g$); Lagrangian $\tfrac12\|\mathbf w\|^2 - \sum_i\alpha_i[y_i(\mathbf w\cdot\mathbf x_i + b) - 1]$; stationarity gives $\mathbf w = \sum_i\alpha_i y_i\mathbf x_i$ and $\sum_i\alpha_i y_i = 0$; substitute to get the dual $\max_{\boldsymbol\alpha}\sum_i\alpha_i - \tfrac12\sum_{ij}\alpha_i\alpha_j y_i y_j\,\mathbf x_i\cdot\mathbf x_j$ with $0 \le \alpha_i \le C$; complementary slackness ($\alpha_i > 0$ only on the street edge or inside it) explains support vectors; $b$ from any support vector with $0 < \alpha_i < C$.
- **The math: how it is solved**: the dual is a quadratic problem in $n$ variables; **SMO** updates two $\alpha$s at a time in closed form (the constraint $\sum\alpha_i y_i = 0$ forces pairs). One slide, no derivation of the clipping; the demos use it.
- **The math: Mercer**: positive semidefinite kernel matrix for every finite set ⇔ a feature map exists (stated); the RBF kernel's feature space is infinite-dimensional (Taylor expansion of $e^{2\gamma\mathbf x\cdot\mathbf z}$, one line).
- **Demo `svmlift`** (new, WebGL via `lib/gl3d.ts`): left, 2D points (presets: ring, two rings, XOR, two blobs; draggable); right, the same points lifted to 3D by a selectable map: $(x_1, x_2, x_1^2 + x_2^2)$, or $(x_1^2, \sqrt2 x_1 x_2, x_2^2)$; orbit with the mouse (drag only, no keys). The separating plane found by a linear SVM in 3D is drawn translucent; its intersection with the lifted surface is projected back as the 2D boundary (a conic). Toggle "show the plane's cut in 2D". Presets: "ring → plane", "XOR needs the $x_1x_2$ coordinate", "two blobs: lifting does not hurt".
- **Demo `svm2d`** with `data-kernel="linear,poly,rbf"`: kernel menu, degree $p$, $\gamma$ slider (log), $C$ slider; background shows $f(\mathbf x)$ with the 0 and ±1 contours; support vectors ringed; optional overlay of each support vector's bump (RBF) as faint circles of radius $1/\sqrt{\gamma}$; optional small panel with the kernel matrix as a heat map (points sorted by class). Presets: "ring: linear fails, RBF works", "XOR: degree 2", "γ too large: islands", "γ too small: a line again", "C and γ both large".
- By hand: (a) verify the quadratic feature map identity for two given vectors, and write the 6-coordinate map for $(\mathbf x\cdot\mathbf z + 1)^2$; (b) evaluate an RBF decision function with 2–3 support vectors at given points and sketch the boundary; (c) for $\gamma = 0.01, 1, 100$ on points spaced about 1 apart, predict the boundary shape; (d) *(math)* solve the dual for two points $\mathbf x_+, \mathbf x_-$ by hand ($\alpha = 2/\|\mathbf x_+ - \mathbf x_-\|^2$) and recover $\mathbf w$, $b$ and the street; (e) *(math)* show that a $2\times2$ "similarity" matrix with a negative eigenvalue cannot be a kernel matrix (find the impossible squared distance).

### 4. `pixel-classify/`: SVMs on images: pixel classification and honest evaluation

- **Pixel classification** (the "trainable segmentation" idea; one-line pointer that interactive segmentation tools work this way): paint a few strokes of each class, compute a **feature stack** per pixel (intensity; Gaussian at $\sigma = 1, 2, 4, 8$; gradient magnitude; LoG / difference of Gaussians; Hessian eigenvalues), train on the painted pixels, classify every pixel. Why several scales: a pixel's own intensity cannot tell nucleus edge from cytoplasm; its neighbourhood can.
- **Feature scaling**: RBF distances mix units; a feature with range 0–4000 drowns one with range 0–1. z-score with **training** statistics (the same z-score as the measurements day). Preset in the demo shows the failure.
- **Train / validation / test**; **$k$-fold cross-validation** over a log grid of $(C, \gamma)$ shown as a heat map; pick the best cell, then test once on held-out labels. Painted pixels are **not independent** (neighbouring pixels of one stroke are almost copies): cross-validate by stroke, not by pixel (one slide; the demo shows the optimistic error otherwise).
- **Class imbalance**: 95 % background makes "always background" 95 % accurate (thresholding day). Remedies: class weights $C_+ \ne C_-$, or move the threshold on $f$. **Evaluation** by confusion matrix and ROC: sweep the offset of $f$ as the thresholding day swept $t$ (recall, pointer; reuse its plots).
- **Multi-class**: one-vs-rest ($K$ classifiers, take the largest $f_k$; scores not calibrated) vs one-vs-one ($K(K-1)/2$ classifiers, vote); picture with three classes and the ambiguous regions. Probabilities: one line (fit a sigmoid to $f$).
- **Smoothing the result**: per-pixel decisions are noisy; the decision value as a graph-cut data term (link to `graphcut-seg/`), one slide.
- **Comparison slide**: SVM vs $k$-NN (no training, all points kept, slow and scale-sensitive; the RBF SVM keeps only support vectors) vs neural networks (learn the features; need more labels; non-convex). When an SVM is a good choice: few labels, tens to a few hundred hand-made features.
- **The math: cross-validation and the grid**: CV error as an estimate of test error; why the test set must be touched once; scaling statistics from training folds only.
- **Demo `pixelsvm`** (new): the micrograph `cell256.png` downsampled to 128×128 (plus a synthetic image with ground truth for the evaluation tab). Paint strokes in 2–3 classes (nucleus, cytoplasm, background; brush size; erase; reset). Feature checkboxes by group and scale; a "show feature" strip of thumbnails; a scatter of painted pixels in two chosen features (with the current decision regions in that 2D slice when only two features are on). Kernel linear/RBF, $C$, $\gamma$; *train* (automatic after each stroke when fast enough); output overlay with opacity, decision-value map. Tab *evaluate* (synthetic image): confusion matrix and ROC from the ground truth, class-weight slider. Tab *cross-validate*: $(C, \gamma)$ heat map with by-stroke vs by-pixel folds. Presets: "intensity only: cytoplasm and background mix", "add smoothing at σ = 4", "boundary class needs gradient features", "unscaled features", "γ too large: speckle", "imbalanced strokes".
- **Demo `svm2d`** with `data-cv="1"`: a held-out test set shown as hollow points, train and test error against $C$ or $\gamma$ (a U-shaped test curve), and a small CV heat map.
- By hand: (a) z-score two features for four training pixels, then classify a test pixel by nearest mean before and after scaling; (b) a 3-class one-vs-rest table of $f_k$ values for four pixels: decisions and which are ambiguous; (c) a confusion matrix of a pixel classifier on an imbalanced image: accuracy vs recall of the rare class; (d) read a CV heat map and pick $(C, \gamma)$; explain why the top-right corner overfits; (e) *(math)* number of classifiers and training-set sizes for OvR vs OvO with $K = 5$.

### 5. (optional / further reading) `detect-window/`: Sliding-window detection with HOG and a linear SVM

- Detection as classification of every window: slide a fixed-size window, compute a descriptor, score with a linear SVM ($f$ is a single dot product per window, so it is fast), keep local maxima above a threshold (**non-maximum suppression**), repeat on a pyramid for several sizes.
- **HOG** (Dalal & Triggs 2005): gradients (Sobel, `kernels/`), histograms of gradient direction in small cells, normalised over blocks (contrast invariance); the learnt $\mathbf w$ drawn as a HOG glyph shows what the detector looks for (the outline of a cell).
- **Hard negative mining**: train, run on background, add the false positives to the negatives, retrain. Evaluation: precision–recall over detections (thresholding day's PR curve), overlap (IoU) to match detections.
- **Demo `hogdetect`** (new): synthetic fluorescence-like images of round cells on a noisy, uneven background (from `lib/shapes.ts` / `lib/imageops.ts` generators, seeded), optionally the micrograph. Panels: the image with a movable window and its HOG glyphs; the learnt weight glyph; detection score map; detections before/after NMS against ground truth. Controls: cell size, bins, window size, $C$, threshold, *mine hard negatives* button. Presets: "a clean set", "touching cells", "different sizes: one scale fails", "after hard negatives".
- By hand: (a) gradient-orientation histogram of a 4×4 cell with given gradients (9 bins); (b) NMS on a list of 6 scored boxes; (c) why a linear SVM on HOG needs only one dot product per window.

## Shared engineering

- `demos/src/lib/svm.ts` (new): SMO with second-order working-set selection (Fan, Chen & Lin 2005) for the soft-margin dual with per-class $C$; linear, polynomial and RBF kernels via a kernel function argument; returns $\boldsymbol\alpha$, $b$, support-vector indices, primal $\mathbf w$ for the linear case, and the dual objective. Kernel cache (full matrix up to ~1000 points). One-vs-rest and one-vs-one wrappers, $k$-fold CV (folds by group id, for by-stroke CV), grid search. A linear subgradient (Pegasos-style) trainer for the "descent" mode and for HOG. Flat `Float64Array`s, no DOM, runs under node.
- `demos/src/lib/svmkernels.ts` (new, or a section of `svm.ts`): kernel functions, explicit quadratic feature maps for `svmlift`, kernel matrix for the heat map. Not called `kernels.ts`, to avoid confusion with convolution kernels (see open questions).
- `demos/src/lib/hog.ts` (new, only if unit 5 is built): cell histograms with bilinear vote, block normalisation (L2-Hys), glyph drawing; gradients from `lib/imageops.ts`.
- **Reused, not duplicated**: `lib/imageops.ts` (image loading, Gaussian at several σ, Sobel, LoG, Gaussian second derivatives / Hessian proposed by the skeleton plan; the feature stack builder `featureStack(img, groups, sigmas)` added there, since other days can use it), `lib/threshold.ts` (thresholding day: confusion matrix, ROC/PR from scores), `lib/plot.ts` (loss curves, ROC, CV heat map, scatter), `lib/gl3d.ts` (`svmlift`), `lib/features.ts` (measurements day; object features for an optional `pixelsvm`/`momentclass` preset), `lib/shapes.ts` (synthetic cells), `lib/linalg.ts` (symmetric eigen for the Mercer check on a small kernel matrix and for Hessian eigenvalues if not in `imageops`), `rng(seed)` from `lib/ui.ts`. If prediction or CV is measured above budget, move `predictRBF` and the SMO inner loop to Rust/Wasm per `demos/README.md`, keeping the TS reference.
- **Tests** (`demos/test/`): the by-hand examples of units 2–3 reproduce exactly (line $x_1 = 1$, support vectors, two-point dual $\alpha$); KKT conditions hold to tolerance on random data; duality gap ≈ 0 (primal objective from $\mathbf w$, $\xi$ vs dual); quadratic kernel = dot product of the explicit map; separable data with large $C$ gives zero training error; SMO vs a brute-force QP (projected gradient) on ≤ 8 points.

## Open questions

- Lagrange multipliers: have the students met them (and inequality constraints)? If not, the dual stays entirely in the math layer, as planned; if yes, the recall slide can go.
- Unit 1 vs the neural-network and moments days: if either is taught first, unit 1 shrinks to a 20-minute recall and units 2–4 get more time (or unit 5 becomes core).
- Unit 5 (HOG detection): optional, as proposed, or core instead of part of unit 4? It is the classic image-specific SVM application, but needs its own descriptor.
- Ground truth for `pixelsvm` on the real micrograph: annotate `cell256.png` (nucleus / cytoplasm / background masks, a one-off manual job; the thresholding plan asks for the same annotation) or evaluate only on synthetic images?
- Kernel naming: `lib/svmkernels.ts` (proposed) vs `lib/kernels.ts`; and on slides "kernel function" or "similarity kernel" consistently, to keep it apart from convolution kernels.
- Should `momentclass` (moments day) get an SVM option, or should object classification have its own preset in `svm2d` with measured features on the axes?
- Is SMO's algorithm worth a slide at all, or is "a standard quadratic solver" enough at this level?
