# Plan: a day on image compression, lossless and lossy

Internal working doc (plan/ is not rendered). Status: draft for discussion, 2026-11-12.

## Goal of the day

After the day a student can:

1. define the **information** of a symbol and the **entropy** $H = -\sum_k p_k \log_2 p_k$ of a histogram, compute $H$ by hand, and state Shannon's source coding theorem ($H$ bits/symbol is the lower bound for a lossless code of independent symbols); name the three redundancies (coding, inter-pixel, psychovisual) and say which step of a codec removes which;
2. build a **Huffman code** by hand, check that it is prefix-free, and compare its average length with $H$ ($H \le \bar L < H + 1$); explain run-length coding, the idea of **arithmetic coding** (one interval for the whole message, so fractional bits per symbol), and **dictionary** coding (LZ77, LZW, DEFLATE in PNG);
3. explain why **prediction** makes images compressible: the residual of a good predictor (DPCM, PNG filters, the median predictor of JPEG-LS) has a narrow histogram and a much lower entropy than the pixel values, and decoding is exact;
4. explain **transform coding** as a change of basis that compacts energy: compute a small **DCT**, recognise the 8×8 DCT basis images, explain why the DCT beats the DFT on blocks (no wrap-around discontinuity), and why the **Karhunen–Loève transform / PCA** is the optimal linear transform and the DCT a fixed approximation of it;
5. walk through the **JPEG pipeline** (colour conversion and chroma subsampling, 8×8 blocks, DCT, quantisation table scaled by a quality factor, zigzag, run-length + Huffman) for one block by hand, predict where **blocking** and **ringing** appear, and relate quantisation step, rate and distortion;
6. measure quality with **MSE / PSNR** and **SSIM**, and show by example that they can disagree;
7. decide for scientific images: when lossy compression is acceptable, what it does to **intensities, texture and small spots**, and which **formats** keep data intact (TIFF/OME-TIFF with LZW/Deflate/zstd, PNG, lossless JPEG 2000 / JPEG-XL, HDF5 and Zarr chunks).

Why it fits this audience: entropy is an expectation over a probability distribution
(basic probability); Huffman coding is a small greedy algorithm on a tree that can be run
on paper; prediction is a difference of neighbours (a derivative), whose histogram they can
count; the DCT is an orthonormal change of basis, so Parseval holds and the squared error
of the image equals the squared error of the coefficients; the KLT is the eigenvector basis
of a covariance matrix. Everything is linear algebra plus counting, and every step can be
done on an 8-pixel row before the demo does it on 256×256.

## Units (one folder each: lec, quiz, exercise with #explore)

Four core units, about 1.5 h each including the exercise, plus one optional unit
(recommended for students who will handle microscopy or medical data).

### 1. `entropy/`: Information, entropy and entropy codes

- Why compress: a 2048×2048×16-bit image is 8 MB; a time-lapse z-stack is terabytes. Lossless (exact) vs lossy (close enough). Compression ratio, bits per pixel (bpp).
- Three redundancies: **coding** (common values get the same number of bits as rare ones), **inter-pixel / spatial** (neighbours are similar), **psychovisual** (detail the eye does not see). Lossless codecs remove the first two; only lossy codecs touch the third. This is the map for the whole day.
- Information of an outcome $I = -\log_2 p$ (a fair coin: 1 bit; one of 256 equally likely grey levels: 8 bits; a sure thing: 0). **Entropy** = expected information. Maximal for a flat histogram ($\log_2 K$), zero for a constant image. Shannon's source coding theorem stated, not proved: no lossless code of independent symbols beats $H$ bits/symbol on average.
- The caveat that drives units 2–3: $H$ of the **grey-level histogram** ignores neighbours. Shuffling the pixels does not change it, but the shuffled image is far harder to compress. Picture: cell image and its pixel-shuffled version, same histogram.
- **Run-length encoding**: (value, run) pairs; great for binary masks and label images (and fax), bad for noisy greyscale. Where it reappears: the zero runs in JPEG (unit 4).
- **Huffman coding** (1952): repeatedly merge the two least probable symbols; read code words from the tree. Prefix-free (no code word is the start of another), so decoding needs no separators. Kraft inequality $\sum 2^{-L_k} \le 1$ in one line. Optimal among symbol-by-symbol codes, $H \le \bar L < H + 1$; the gap is large when one symbol has $p \gg 0.5$ (a mostly-black mask: Huffman cannot use less than 1 bit/pixel, RLE or arithmetic coding can).
- **Arithmetic coding** (idea, one picture): the message narrows the interval $[0,1)$ by each symbol's probability; the final interval width is $\prod p$, so about $-\log_2 \prod p = \sum I$ bits, i.e. fractional bits per symbol. Context-adaptive binary arithmetic coders (CABAC, JPEG 2000's MQ coder, JPEG-XL's ANS) named.
- **Demo `huffman`** (new): an editable histogram of up to 12 symbols (drag bar heights, or load the histogram of a chosen image patch: a cell-image crop, a binary mask, a noise patch, the residuals from unit 2). Shows: the Huffman tree built step by step (*next merge* / *build all* / *reset*, the two merged nodes highlighted), the code table (symbol, $p$, $-\log_2 p$, code word, length), and a bar comparing $H$, $\bar L$ and the fixed-length $\lceil\log_2 K\rceil$. Toggle tie-breaking rule (different trees, same $\bar L$). A second panel encodes a short symbol string with the current code and shows the bit string, with decoding by walking the tree. Optional tab *arithmetic*: the nested intervals for a 4–6 symbol message. Presets: "flat histogram: no gain", "one dominant symbol: Huffman ≥ 1 bit", "dyadic probabilities: $\bar L = H$ exactly", "binary mask: RLE wins", "residuals from unit 2".
- By hand: $H$ of $p = (0.4, 0.2, 0.2, 0.1, 0.1)$ ($\approx 2.12$ bits); build the Huffman tree, code lengths and $\bar L$ (2.2 bits); show two valid trees with different lengths but the same $\bar L$; RLE a binary row of 16 pixels; $H$ of a 4×4 image from its histogram, and of the same values shuffled.

### 2. `lossless/`: Prediction, dictionaries and lossless formats

- Inter-pixel redundancy: plot each pixel against its left neighbour (a tight diagonal cloud). The new information in a pixel is what its neighbours did **not** predict.
- **Predictive coding / DPCM**: residual $e = I - \hat I$ with $\hat I$ from already-decoded neighbours (left; up; average; planar $a + b - c$). The decoder makes the same prediction and adds $e$ back: exact. The residual histogram is narrow and centred at 0 (roughly Laplacian), so its entropy is a few bits lower than the pixel histogram; the coder from unit 1 then wins. Link: the residual is a finite-difference derivative (*Filtering & convolution*); edges are where prediction fails.
- **PNG** filters per row (None, Sub, Up, Average, Paeth) chosen by a heuristic, then DEFLATE. **JPEG-LS / LOCO-I**: the median edge detector (MED) predictor, context modelling of residuals, Golomb–Rice codes (named). Noise sets the floor: the residual can never be narrower than the noise, which is why lossless ratios for noisy microscopy are typically only 1.5–3×.
- **Dictionary methods**: LZ77 (sliding window, (distance, length, next) triples; repeats are cheap), LZW (growing dictionary of strings; GIF, TIFF-LZW). **DEFLATE** = LZ77 + Huffman (zip, gzip, PNG, TIFF-Deflate); zstd as the modern successor (OME-Zarr, TIFF). They need **exact** repeats, which noisy pixel values rarely have: that is why prediction comes first.
- Modern lossless: JPEG-XL lossless (predictors + context modelling + ANS), lossless JPEG 2000 (reversible 5/3 wavelet, see unit 5); typical ratios on photos vs micrographs in a table.
- **Demo `predict`** (new, main demo): the micrograph `cell256.png` (also a synthetic smooth image, a noisy flat field, a binary mask, and a 12-bit synthetic fluorescence image from the bit-depth day's generator). Predictor menu: none, left, up, average, planar, Paeth, MED. Panels: image, residual image (diverging map, 0 = grey), histograms of pixels and residuals on the same axis, with $H$ of each and the scatter of pixel vs left neighbour. Readout: entropy (bits/pixel), "ideal size" = $H \cdot N$, and the **real DEFLATE size** of the raw and residual bytes from the browser's built-in `CompressionStream("deflate")` (no network, no library). A noise slider (added Gaussian noise) shows the floor. Click a pixel to see its neighbours, prediction and residual. Presets: "left neighbour on the cell", "noise kills prediction", "edges are what remains", "MED vs average at a diagonal edge", "binary mask: RLE/LZ territory".
- **Demo `lzstep`** (new, small): a short string or one image row of small integers; step through LZ77 (window, longest match, emitted triple) or LZW (dictionary growing, emitted codes), with the output length against the input length. Presets: a repetitive row, a noisy row, "ABABABA".
- By hand: residuals of the row 100 102 104 103 105 107 106 108 with the left predictor; $H$ of pixels (3 bits) vs residuals (≈ 0.86 bits); decode the residuals back; Paeth prediction for three given neighbour triples; LZW-encode "ABABABA" and decode it.

### 3. `dct/`: Transform coding, the DCT and the KLT

- Recall from `fourier/` (one line, one screenshot): keeping the largest 3% of the Fourier coefficients keeps most of the image. Transform coding makes this a codec: **transform** (decorrelate, compact energy) → **quantise** (the only lossy step) → **entropy code** (units 1–2).
- **Energy compaction**: for an orthonormal transform $c = A x$, $\|c\|^2 = \|x\|^2$ (Parseval) and the squared error of dropped or quantised coefficients is the squared error of the image. A good transform puts most of $\|x\|^2$ in few coefficients. Two-pixel picture: correlated pairs $(x_1, x_2)$ lie near the diagonal; rotate by 45° → $(x_1 + x_2)/\sqrt2$ carries almost everything, $(x_1 - x_2)/\sqrt2$ almost nothing.
- **The KLT is that rotation in general**: eigenvectors of the covariance matrix of blocks (PCA; recall in one slide). It is the optimal linear transform for compaction (decorrelates exactly, maximises energy in the first $k$ coefficients), but it depends on the data and must be stored and computed.
- **The DCT** (DCT-II, orthonormal): $c_k = \alpha_k \sum_{n=0}^{N-1} x_n \cos\!\big(\pi (2n+1) k / 2N\big)$. A real, Fourier-type basis of cosines; for a stationary first-order Markov (AR(1)) signal with correlation $\rho \to 1$ it approaches the KLT, so it is a fixed, fast, near-optimal choice. 2D: separable, $C = D X D^\top$; the 64 **8×8 basis images**.
- **Why not the DFT**: the DFT treats a block as periodic, so the jump between its right and left edge adds high-frequency energy (slow $1/k$ decay); the DCT is the DFT of the block **mirrored**, which has no jump ($1/k^2$ decay). Picture: a ramp row, its periodic and its mirrored extension, both coefficient sequences. This is also how the DCT is computed with `fft.ts`.
- Why blocks: local statistics, small transforms, memory. The cost: block boundaries (unit 4). Cross-references: wavelets as the multiresolution alternative (wavelets day); Legendre truncation in the moments day is the same projection argument in a polynomial basis.
- **Demo `dctblock`** (new): left, the image (cell, a photo, synthetic edge/ramp/texture) with a movable 8×8 block selector; middle, the block zoomed (pixels with values) and its 64 DCT coefficients as a heat map with numbers; right, the 8×8 basis images, hover-free: click a basis image to add or remove it, or slide *keep k largest* / *keep first k in zigzag order*, with the reconstructed block and its error. Basis menu: **DCT**, **DFT (real part / magnitude)**, **KLT** learnt from all 8×8 blocks of the current image (eigen-patches shown in the same grid, ordered by eigenvalue, with an energy curve against the DCT's). A 1D tab (`data-mode="1d"`): one 8-sample row, its periodic vs mirrored extension, DFT vs DCT coefficients. Presets: "flat block: only DC", "vertical edge: one row of coefficients", "ramp: DFT leaks, DCT does not", "texture block", "KLT looks like the DCT".
- **Extend `fourier2d`** (existing demo, not a new one): `data-basis="dft|dct|dct8"` so the *keep largest x%* mode can compare, at the same kept fraction, the whole-image DFT, the whole-image DCT (no wrap-around artefacts at the image border) and the 8×8 block DCT. Same image, same readouts (variation kept, RMS error) as in `fourier/`, so E2 there can be compared directly.
- By hand: the 2-point DCT is the 45° rotation above; 4-point DCT matrix (given), apply it to $(1,1,1,1)$ and $(1,2,3,4)$, check orthonormality of two rows; covariance $\begin{pmatrix}1 & \rho\\ \rho & 1\end{pmatrix}$, its eigenvectors and eigenvalues $1 \pm \rho$, and the fraction of energy in the first; Parseval: error of dropping two given coefficients.

### 4. `jpeg/`: The JPEG pipeline, artefacts and quality metrics

- The pipeline, one slide each, on one block of the cell image:
  1. **Colour**: Y′CbCr and 4:2:0 subsampling (recall; owned by the colour day, unit 2).
  2. Level shift ($-128$) and **8×8 blocks**.
  3. **DCT** (unit 3).
  4. **Quantisation**: $q_{uv} = \mathrm{round}(c_{uv} / Q_{uv})$ with the standard luminance table (small steps at low frequency, large at high: the psychovisual redundancy as a matrix). **Quality factor** scales the table (IJG formula: $s = 5000/q$ for $q < 50$, $200 - 2q$ otherwise). This is the only lossy step after subsampling.
  5. **Zigzag** order: low to high frequency, so the many zeros come last.
  6. **Entropy coding**: DC coded as the difference from the previous block (DPCM, unit 2); AC as (zero-run, size) symbols + amplitude bits, Huffman-coded (unit 1), with end-of-block. Progressive JPEG and arithmetic-coded JPEG named.
  Decoding reverses each step; only rounding in step 4 (and subsampling) loses information.
- **Rate and distortion**: quantising a coefficient with step $\Delta$ gives error variance $\approx \Delta^2/12$ (bit-depth day, unit 1), carried unchanged to the image because the DCT is orthonormal; halving $\Delta$ costs about one bit per significant coefficient and buys 6 dB. Rate–distortion curve (PSNR vs bpp) as the way to compare codecs; dead-zone quantisers in one line.
- **Artefacts**: **blocking** (each block quantised independently; flat regions become flat blocks with steps at 8-pixel boundaries), **ringing / mosquito noise** (dropped high frequencies around edges: Gibbs, as in `fourier/` low-pass), colour bleeding (subsampled chroma), loss of fine texture. Repeated recompression (generation loss) and JPEG at different grid offsets.
- **Quality metrics**: MSE, **PSNR** $= 10\log_{10}(255^2/\mathrm{MSE})$ (peak for 8 bit; a 16-bit image needs $65535^2$ or its real range). **SSIM** (Wang et al. 2004): local comparison of mean, variance and covariance in a Gaussian window, $\frac{(2\mu_x\mu_y + C_1)(2\sigma_{xy} + C_2)}{(\mu_x^2 + \mu_y^2 + C_1)(\sigma_x^2 + \sigma_y^2 + C_2)}$, with an SSIM map. They disagree: a brightness shift has a large MSE but looks fine; blocking with a small MSE looks bad. Neither measures what an analysis needs (unit 5).
- **Demo `jpeg`** (new, main demo of the day): a greyscale or colour image (cell image, a photo, a synthetic test card with edges, text and a smooth gradient), quality slider 1–100, chroma 4:4:4 / 4:2:0, custom table mode (edit $Q$ or scale low/high frequencies separately), uniform table option ("all steps equal" vs perceptual table). Panels: original | decoded | difference (or SSIM map) with a shared zoom lens; a selected block with its coefficients before and after quantisation, the zigzag sequence and the (run, size) symbols; the quantisation table. Readout: number of non-zero coefficients, **estimated size** in bytes and bpp from the actual Huffman bit count with the standard tables (and, as a cross-check, the size of the browser's own `canvas.toBlob("image/jpeg", q)`), compression ratio, PSNR, SSIM; a small rate–distortion plot with the current point and the curve over all qualities. Toggle "deblock" (simple boundary smoothing) optional. Presets: "quality 90: invisible", "quality 10: blocking in the background", "ringing at the cell edge", "colour bleeding (4:2:0 on a red/blue edge)", "flat table vs JPEG table at the same size", "recompress 10× at quality 75".
- **Demo `samemse`** (new, small): one image distorted in five ways (brightness shift, contrast stretch, Gaussian noise, blur, JPEG), each tuned (bisection on its parameter) to the **same MSE**, shown side by side with PSNR (all equal) and SSIM (very different). A slider sets the common MSE. Preset "Wang–Bovik": the classic figure on the cell image.
- By hand: quantise a given 4×4 (or 8×8, mostly zeros) coefficient block with a given table, write the zigzag sequence and the (run, size) pairs with EOB, count bits with a given table; dequantise and give the maximal error per coefficient ($Q_{uv}/2$); scale a table entry for $q = 25$ and $q = 75$; PSNR of a 3×3 image with a given error; SSIM of a constant-offset pair (structure term = 1, luminance term < 1).

### 5. (optional / recommended for microscopy and medical students) `compress-science/`: Compression and measurements, JPEG 2000, formats

- **Images are data**: lossy compression changes pixel values in a structured, content-dependent way (not independent noise). Consequences: integrated intensities of small spots drop (high frequencies quantised away), dim spots near the noise vanish or merge, texture features (variance, co-occurrence, power spectrum) shift towards smooth, blocking adds an 8-pixel periodic structure (visible as peaks in the Fourier spectrum: link to `fourier/`), background levels change, and baseline JPEG forces 16-bit data to 8 bits (bit-depth day). Journal and community guidance: store raw/lossless, compress only copies for display.
- **JPEG 2000 as an application** (theory on the wavelets day): tiles → DWT (irreversible 9/7 for lossy, **reversible integer 5/3 via lifting** for exactly lossless) → quantisation → **embedded bit-plane coding** (EBCOT + MQ arithmetic coder) → a code stream that can be truncated at any rate, decoded at lower resolution, or by region. No blocking: errors appear as blur and ringing instead. Where it is used: whole-slide pathology images (multi-gigapixel pyramids), DICOM, cultural-heritage archives. JPEG-XL and HTJ2K named as successors.
- **Formats** (one table, briefly): TIFF / **OME-TIFF** (8/16/32-bit, float, multi-channel/z/t, compression none / LZW / Deflate / zstd / JPEG, pyramids), PNG (lossless, ≤ 16 bit, 2D), JPEG (8-bit, lossy), JPEG 2000 (lossless or lossy, high bit depth, pathology/DICOM), JPEG-XL, DICOM (container, carries JPEG-LS / JPEG 2000 / lossless JPEG), **HDF5** and **Zarr / OME-Zarr** (chunked n-D arrays, each chunk compressed independently with Blosc/zstd/LZ4, so a region is read without decompressing the whole file; chunk shape vs access pattern). Shuffle/bit-shuffle filters as "prediction for bytes" (link to unit 2).
- **Demo `measuredamage`** (new): a synthetic fluorescence image with known ground truth (seeded: 60 Gaussian spots of varying brightness and size on a cell-shaped background with Poisson noise, 12-bit) plus the cell micrograph. Codec menu: lossless (PNG/DEFLATE), JPEG at quality $q$ (the `jpeg` pipeline from `lib/jpeg.ts`, after a 16→8-bit rescale), and, if `lib/wavelet.ts` from the wavelets day exists, a simple wavelet codec at matched size. Measurements on original and decoded image: spot count (threshold + labelling), per-spot integrated intensity error (scatter plot true vs measured), background mean and standard deviation, a texture measure (local variance or high-frequency power), and the power spectrum with the 8-pixel blocking peaks. A plot of each measurement against bpp across the quality range. Presets: "quality 95 looks perfect: integrated intensity of dim spots −x%", "quality 30: spots lost, others merged", "blocking peaks in the spectrum", "lossless: identical numbers, 2× smaller", "same size, wavelet vs JPEG".
- By hand: storage of a given time-lapse z-stack raw vs at a 2.5× lossless ratio; which format for four scenarios (16-bit confocal stack to analyse; figure for a paper; slide scanner archive; web viewer of a large volume with region access); number of chunks read for a given region and chunk shape.
